# Qihang Handbook GUI V3 重构工作计划

## 1. 重构目标

当前编辑器的核心问题不是功能不够，而是信息架构和渲染模型混在了一起：

- 三栏布局把注意力拆散了，主预览不够集中。
- 预览层、编辑层、数据层互相耦合，导致模板效果和编辑器效果不一致。
- 资源、规则、源码、元素属性全部常驻，工作台显得拥挤。
- 当前数据模型仍然保留了“点位重建”的思路，和 `html/handbook-template.html` 的原始视觉结构不完全一致。

本次重构目标是把项目收敛成一个明确的工具：

- 主画布始终居中，作为唯一主视觉。
- 左右面板改为可折叠抽屉，按需出现。
- 预览直接以原始 HTML 模板为准，不再用拆点重建来替代真实模板。
- 编辑能力围绕“模板检查、局部修正、资源管理、导出”展开。

## 2. 现状基线

当前关键文件和职责：

- [`html/handbook-template.html`](/home/zza/qihang-handbook-gui-v3/html/handbook-template.html): 原始模板，视觉效果基准。
- [`src/App.tsx`](/home/zza/qihang-handbook-gui-v3/src/App.tsx): 编辑器入口，包含预览、选择、规则检查、导出等逻辑。
- [`src/data.ts`](/home/zza/qihang-handbook-gui-v3/src/data.ts): 默认项目数据，仍以手写页面模型为主。
- [`src/types.ts`](/home/zza/qihang-handbook-gui-v3/src/types.ts): 页面、元素、样式、资源的数据结构。
- [`docs/PROJECT_INFO.md`](/home/zza/qihang-handbook-gui-v3/docs/PROJECT_INFO.md): 项目概览。

已确认的技术事实：

- 直接打开 `html/handbook-template.html` 的视觉效果是正确的。
- 编辑器中必须通过 `srcDoc` / iframe 渲染模板，否则样式会被破坏。
- 模板里的图片路径是相对 `html/` 目录解析的，不能按应用根目录随意替换。

## 3. 重构范围

本次重构只处理编辑器主工作台，不改动 electron 打包链路，不改动模板本身的视觉稿，不改动现有构建命令。

重点范围：

- 页面布局重构
- 预览管线重构
- 左右抽屉拆分
- 数据模型整理
- 导入 / 导出链路整理
- 验收和回归补强

暂不纳入本轮的内容：

- 模板视觉稿重新设计
- electron 原生窗口样式重写
- 大规模页面语义化抽象
- 服务端化存储

## 4. 详细执行方案

### 4.1 页面布局重构

目标：

- 把三栏布局改成“顶部工具条 + 中央主画布 + 左右可折叠抽屉”。
- 默认状态下只突出中央画布。
- 左右侧栏不再永久占位。

实现方式：

1. 在 `src/App.tsx` 里增加统一布局状态，例如：
   - `leftPanelOpen`
   - `rightPanelOpen`
   - `focusMode`
   - `activeSidebarTab`

2. 把当前 `.app-shell` 的三列 grid 改成中间主区优先的结构。

3. 左右面板改成抽屉式组件：
   - 桌面端可从边缘展开。
   - 窄屏下默认折叠为按钮或抽屉。
   - 打开某个面板时自动关闭另一侧，避免视觉竞争。

4. 顶部工具条只保留高频操作：
   - 导入
   - 导出
   - 缩放
   - 撤销 / 重做
   - 左右面板开关

验收标准：

- 1440px 视口下，主画布占据绝对视觉中心。
- 左右面板收起时不占固定宽度。
- 1024px 以下不会出现面板挤压导致的内容错位。

### 4.2 预览管线重构

目标：

- 让编辑器预览与直接打开 `html/handbook-template.html` 尽量一致。
- 预览只负责注入必要的 CSS 和路径基准，不再重组模板结构。

实现方式：

1. 在 `src/App.tsx` 中保留 `sourceDocumentHtml` 作为完整源文档。

2. 预览时使用 `iframe srcDoc` 直接渲染源 HTML。

3. 对 `srcDoc` 注入：
   - `<base href="./html/">` 或对应的资源基准路径
   - 当前编辑后的 `style` 标签
   - 选中态高亮样式

4. 取消“把页面拆成元素后再拼回去”作为主预览路径，避免 grid、flex、伪元素、媒体查询失真。

5. 保留元素拆解能力，但只用于：
   - 检查器定位
   - 局部样式编辑
   - 规则命中提示

验收标准：

- 预览在等待加载后与原 HTML 视觉一致。
- 模板中的标题、版式、装饰层、背景层不再被破坏。
- 资源路径按 `html/` 目录基准解析正确。

### 4.3 左侧资源抽屉

目标：

- 左侧只负责“内容输入”和“页面导航”。
- 不再把过多编辑能力塞进资源区。

实现方式：

1. 左侧抽屉拆成两个区块：
   - 页面列表
   - 资源库

2. 页面列表保留：
   - 页面标题
   - 页面规则数
   - 页面元素数
   - 当前页面高亮

3. 资源库保留：
   - 导入 HTML
   - 导入图片
   - 资源缩略图
   - 缺失资源提示

4. 如果资源很多，增加过滤或分组：
   - 图片
   - 字体
   - 外链资源
   - 缺失资源

5. 左侧抽屉默认收起为窄栏或图标栏，避免抢占主画布宽度。

验收标准：

- 导入素材后能马上看到资源条目。
- 页面列表可切换页面，不会打断当前工作状态。
- 资源区不再承担 CSS 编辑职责。

### 4.4 右侧检查抽屉

目标：

- 右侧专注“当前选中对象的检查与局部修正”。
- 让它更像 inspector，而不是第二个编辑器。

实现方式：

1. 右侧抽屉按标签页拆分：
   - 检查器
   - 规则
   - 源码

2. 检查器页保留：
   - 当前选中元素名称
   - 类名 / ID
   - 内联样式
   - 选中元素命中的规则列表

3. 规则页保留：
   - 当前页面 CSS 规则列表
   - 规则搜索
   - 规则编辑 / 删除 / 新建

4. 源码页保留：
   - 当前页面 CSS 源码
   - 手动应用源码
   - 解析失败提示

5. 右侧抽屉默认只展开当前最常用的 inspector 页签，其余页签按需切换。

验收标准：

- 点选模板元素后，右侧能准确显示元素信息。
- 规则编辑不会影响主预览的结构稳定性。
- 源码页能作为高级兜底，不影响常规操作。

### 4.5 数据模型整理

目标：

- 把“原始模板”“页面语义”“资源”“编辑状态”分层。
- 减少 `App.tsx` 里同时处理过多职责的情况。

实现方式：

1. 扩展页面模型，明确区分：
   - `templateHtml`
   - `sourceDocumentHtml`
   - `stylesheet`
   - `elements`

2. 默认项目保留为 demo 数据，不作为正式工作流唯一入口。

3. `src/data.ts` 逐步从“手写布局模板”转为“演示样例”职责。

4. 如果后续继续重构，把页面元素进一步语义化：
   - title
   - subtitle
   - hero
   - card
   - body
   - footer

5. `src/types.ts` 中的数据结构只保留项目运行必须字段，避免冗余字段继续膨胀。

验收标准：

- 页面数据和模板源文档能分开维护。
- 编辑器状态刷新后不丢失当前页面定义。
- 类型定义不再让 `App.tsx` 里到处出现临时约定。

### 4.6 导入 / 导出链路

目标：

- 导入和导出都围绕原始模板文档走。
- 导出结果应尽量接近直接打开的 HTML 文件。

实现方式：

1. 导入 HTML：
   - 读取完整文件内容
   - 提取 CSS
   - 建立页面列表和资源索引
   - 保留源文档内容

2. 导入图片：
   - 建立资源对象
   - 自动匹配页面中的引用
   - 选中图像元素时允许替换资源

3. 导出 HTML：
   - 优先输出基于 `sourceDocumentHtml` 注入后的完整文档
   - 只有在没有源文档时，才退回到拼接式导出

4. 导出前加检查：
   - 是否有缺失资源
   - 是否有 CSS 解析失败
   - 是否存在未保存草稿

验收标准：

- 导出文件可直接打开。
- 导出后的视觉效果不依赖编辑器内部状态。
- 图片资源路径和注入样式不互相冲突。

### 4.7 验收与回归

目标：

- 每次改动都能确认没有把主预览弄坏。

实现方式：

1. 固定最少一张截图基线：
   - 原始模板直接打开
   - 编辑器预览
   - 导出后的 HTML

2. 每次布局调整后，确认：
   - 页面不空白
   - 标题不挤压
   - 抽屉收起后主画布仍完整

3. 每次导入逻辑调整后，确认：
   - 页面列表正常
   - 资源路径正常
   - CSS 规则仍可命中

4. 每次导出逻辑调整后，确认：
   - 输出文件可以独立打开
   - 图片没有全部丢失
   - 视觉层次没有明显偏移

## 5. 推荐实施顺序

建议按下面顺序执行，避免重构时一直被旧结构拖住：

1. 先做布局骨架，砍掉常驻三栏。
2. 再统一预览管线，保证模板显示正确。
3. 再拆左右抽屉。
4. 再整理数据模型。
5. 再修导入导出。
6. 最后补验收和截图回归。

## 6. 风险点

- 资源路径基准处理不正确，会导致模板图片再次丢失。
- 如果继续保留“元素坐标重建”作为主路径，模板效果还会反复失真。
- 抽屉化后如果没有统一状态管理，面板打开/关闭会变乱。
- 导出逻辑如果不基于源文档，最终结果会和预览不一致。

## 7. 结论

这个项目的重构核心，不是再加一个面板，而是把编辑器从“多功能并列工具”改成“主画布驱动的模板工作台”。  
只要预览层、数据层、资源层、检查层分开，后面的功能扩展才不会继续把界面做散。
